# ansi-cl-spec

An EPUB 3 edition of the draft ANSI Common Lisp standard. **The edition is the source of
truth**: `src/` is the unpacked EPUB and is edited directly; the `.epub` is built from it.

## Layout

- `original/` the untouched input EPUB (provenance); git tag `v0-original` is the first import.
- `src/` unpacked EPUB tree (`mimetype`, `META-INF/`, `OEBPS/`).
- `tools/` Python tooling (`build.py`, `audit.py`, `roundtrip.py`); `tools/lisp/` SBCL scripts;
  `tools/data/cl-symbols.txt` the 978 external `COMMON-LISP` symbols.
- Content layout (`src/OEBPS/text/`): `cover.xhtml`, `<n>-<title-slug>/` per chapter (`14-conses/`,
  `A-appendix/`, `26-glossary/`) holding `index.xhtml` (chapter), `<secno>-<slug>.xhtml` (sections,
  e.g. `14.1-cons-concepts`) and dictionary entries (`14.2.9-car.xhtml`), plus `index/<letter>.xhtml`.
  Glossary letters are `26-glossary/<letter>.xhtml`. The section number makes every name unique;
  the slug is only for readability. `tools/data/path-map.json` maps the original flat names
  (`c14`, `s14-1`, `e14-2-9`, `g-a`, `i-a`) to these paths; `tools/rename_map.py`,
  `rename_apply.py` and `verify_rename.py` produced and checked that one-time rename.
- `tests/` pytest suite for the tools (small fixture trees, not the real book).
- `dist/` build output (git-ignored): `ANSI-Common-Lisp.epub`, `inventory.json`, `inventory.LICENSE`, `epubcheck.txt`, `audit.json`,
  and `site/` (the web edition, from `tools/build_site.py`).
- `.github/workflows/pages.yml` tests, checks, and publishes the web edition on every push to `main`.

## Use

- `./build.sh [--src DIR] [--out FILE]` builds a deterministic EPUB (`dist/ANSI-Common-Lisp.epub`).
  `SOURCE_DATE_EPOCH` sets the timestamps (default 1980-01-01).
- `./check.sh [--roundtrip] [audit options]` builds, regenerates and diffs the CL symbol list,
  runs `epubcheck` (any fatal/error/warning fails), and runs `tools/audit.py` (internal links and
  fragments, duplicate ids, manifest, CL symbol coverage). `--require-anchors` makes a missing
  `data-symbol` anchor an error. `--roundtrip` also compares the build with `original/`
  (meaningful only on an unedited `src/`).
- `python3 -m pytest -q` runs the tool tests.

## Web edition

The edition is published at **https://symbolics.github.io/ansi-cl-spec/** by the `Pages` workflow
(`.github/workflows/pages.yml`): on each push to `main` it runs the tests and `./check.sh --require-anchors`,
then `tools/build_site.py`, and deploys `dist/site/`. To build the site locally: `./build.sh && python3 tools/build_site.py`.

- The pages are `src/OEBPS/` served unchanged, so **a page's URL is the site address plus its path relative
  to `OEBPS/`**: `https://symbolics.github.io/ansi-cl-spec/text/14-conses/14.2.9-car.xhtml#cadr`. That is the
  site address plus an inventory `href`. Other documentation links here, so paths and anchors are a
  permanent contract: don't rename files or anchors without keeping the old address working.
- The site root also serves `index.html` (a generated landing page), `ANSI-Common-Lisp.epub`,
  `inventory.json` and `inventory.LICENSE`.
- **Short symbol links** (`s/` is reserved for them; generated by `tools/site/shortlinks.py`):
  `https://symbolics.github.io/ansi-cl-spec/s/cadr` goes to the page and anchor of `cadr`. Every symbol has
  `s/<slug>` and every inventory record has the precise `s/<slug>.<kind>` (e.g. `/s/list.function`,
  `/s/list.system-class`). A symbol with one meaning redirects; one with several (e.g. `/s/list`) gets a
  small page listing each meaning. The pages are `.html` files (Pages serves them without the extension)
  and redirect with `<meta http-equiv="refresh">`, a canonical link and `location.replace`, so they work
  without JavaScript. `s/index.html` lists all symbols. The **slug rule** (permanent; `tools/site/slug.py`):
  the name in lower case; `a-z 0-9 - * + = &` are kept; `/` becomes `_sl`, `<` becomes `_lt`, `>` becomes
  `_gt`; `(setf x)` becomes `setf-` plus the slug of `x`; any other character is an error, and so are
  empty slugs and two symbols with the same slug (the build fails). Examples: `cadr` → `cadr`,
  `*print-base*` → `*print-base*`, `&optional` → `&optional`, `1+` → `1+`, `/=` → `_sl=`, `<=` → `_lt=`,
  `>=` → `_gt=`, `string/=` → `string_sl=`, `/` → `_sl`, `//` → `_sl_sl`,
  `(setf documentation)` → `setf-documentation`. The inventory's `short` field has the precise path.
- Anything web-only is generated by `tools/build_site.py` and is never written into `src/`. The EPUB stays
  the source of truth. The build copies the pages and splices static navigation into each copy (text
  splicing; element ids and page paths are unchanged, no JavaScript needed): a viewport tag, `rel=prev/next/up`
  links, a header with the edition title, a Contents link and breadcrumbs (Contents › 14 Conses › 14.2 …),
  and a footer with previous / up / next links and the copyright notice. Previous/next follow the spine
  (minus the cover); up is the parent of the page's table-of-contents entry. Styling is
  `assets/site.css` (classes prefixed `site-`). The code is in `tools/site/` (`toc.py`, `chrome.py`,
  `check.py`, `slug.py`, `shortlinks.py`).
- **Search** (`assets/site.js`, no dependencies; needs JavaScript, everything else works without): a search box
  in every page header, on the landing page and on the `s/` chooser and list pages. It loads `search.json`
  on first use. Press `/` to focus it; type; Up/Down move the highlight, Enter opens the highlighted result
  (the first if none), Escape clears (and, when empty, leaves the box); clicking a result works too. Matches
  are case-insensitive on the label: exact, then prefix, then substring; symbols before sections before
  glossary terms; shorter labels first; at most 20 are shown. `search.json` (generated by
  `tools/site/indexes.py`, about 350 KB) is `{"v": 1, "items": [[label, kind, href, type, full], ...]}`:
  `type` is 0 symbol (one per inventory record; `kind` is `"<kind> · <secno>"`), 1 section (every
  table-of-contents entry; `full` holds the complete title when `label` is shortened), 2 glossary term
  (`href` is the glossary page and the term's anchor); `href` is relative to the site root. Every item's
  file and anchor is verified by the site check.
- The build ends by running `python3 tools/site/check.py dist/site`: every page must parse as XML and every
  relative link and fragment (including `<meta http-equiv="refresh">` targets) must resolve (the build fails otherwise; `--no-check` skips it).

## Symbol inventory

`./build.sh` (and `./check.sh`) also write `dist/inventory.json` and `dist/inventory.LICENSE`, generated by
`tools/09_inventory.py`: a machine-readable symbol to location inventory, intended as the default spec
inventory of cl-doc. It is published under the **Microsoft Public License (Ms-PL)**, copyright 2026
Symbolics Pte Ltd, separately from the edition's own terms; `inventory.LICENSE` is the verbatim Ms-PL text
(`tools/data/MS-PL.txt`, from SPDX) and applies to `inventory.json` only.

Schema (format `ansi-cl-spec-inventory`, version 1): a header (`edition` with title, identifier,
`dcterms:modified` and source from the OPF; `license`, `license_file`, `copyright`, `site` (the web edition's base URL), `base`, `counts`) and
`entries`, one record per element carrying `data-symbol` (symbol name, anchor location), sorted by
(symbol, path, anchor): `symbol` (as printed), `package` (`COMMON-LISP` or null; `setf: true` for
`(setf name)`), `kind` (the entry's `data-kind`, or `lambda-list-keyword`, `optimize-quality`,
`documentation-type`, `method-combination-type`, `case-clause-key` for the 18 non-entry anchors), `path`
(relative to `OEBPS/`), `anchor` (raw id), `href` (path plus URL-encoded fragment, as the book's own links),
`short` (`s/<slug>.<kind>`, the site-relative short link without extension, not URL-encoded; see Web edition),
`secno`, `title`, and `legacy` (`path`, `id` in the original pre-rename edition). A symbol with several
meanings (e.g. `list` as system class and function) has several records. Output is deterministic;
`check.sh` builds it twice, compares, and checks coverage of the 978 CL symbols, record count and links.

## Re-running the audits

The committed results are in `audit/text/` (EPUB vs dpANS3R text) and `audit/examples/` (the spec's
examples run in SBCL). The tools find dictionary entries by markup (`h3.entry`, recursively), so they
work on the renamed layout in `src/` and on the original flat layout (e.g. a `git archive v0-original
src/OEBPS/text` export passed as `--epub` / `--text-dir`). Results are keyed by section number and
names; file paths are reported relative to `OEBPS/`. To re-run without overwriting the committed
results, send the output elsewhere:

    python3 tools/compare_text.py --epub src/OEBPS/text --out /tmp/audit-text   # fetches dpANS3R into vendor/dpans (or pass --tex DIR)
    python3 tools/examples_run.py --text-dir src/OEBPS/text --out-dir /tmp/audit-examples

Expected: text, 3858/3917 sections at ratio 1.0 and 0 unmatched (the 25 below 1.0 since the errata
corrections are intended deviations, listed in the History note of `audit/text/summary.md`); examples,
match 2250, mismatch 114, error 145, impl-dependent 177, no-expectation 204, skipped 152, unparsed 34.
The summaries' History notes are written by hand and are not regenerated. The examples run needs
`sbcl`; some actual values (timestamps, temp paths, object addresses) differ from run to run, the
classifications do not.

## Tooling policy

Python 3 (stdlib + lxml; pytest for tests). SBCL is used only to run the spec's examples and to
list the `COMMON-LISP` external symbols. Edits to `src/` are targeted text changes, so diffs stay
reviewable.
